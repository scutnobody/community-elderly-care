# 课程验收操作与证据记录

本文件是可重复操作清单，不是预先填写的“全部通过”结论。每次验收记录日期、代码版本、Python 版本、机器、数据库/附件目录和实际输出。所有破坏性或大数据实验只在独立数据目录执行；不启动 README 旧公网地址。

## 一、准备与回归

1. 停止全部写入者；执行 README 的离线备份和 verify。保留原始 ZIP、数据库和 uploads。
2. `python -m unittest discover -s tests -t . -v`。这些测试使用临时库，记录通过数、失败测试名和异常；失败不能省略。
3. `python server.py --data-dir C:\care-acceptance-demo --port 8081`，另开终端执行 `python api_smoke_test.py --base-url http://127.0.0.1:8081 --confirm-isolated`。脚本写入隔离库，输出测试订单号。
4. 停止再启动同一目录；按订单号查询刚创建的订单。比较老人、项目、用药、就诊、投诉及附件是否仍在。不得借 `--reset` 消除问题。

## 二、需求覆盖与人工检查

| 需求范围 | 操作和证据 | 判定边界 |
|---|---|---|
| 预约、派单、履约 | 用三角色完成冒烟；另测无效日期、非正时长、助餐/助医缺失字段；两个并发重叠请求只允许一单，结束相接可派；跳过到达应失败 | 脚本走真实 HTTP 与 SQL；并发控制还须看自动化结果 |
| 人员资格、资质审核 | 人员提交证书后不能立即取得资格；管理员核对姓名、编号、有效期再审核；离职、区域、类型、证书过期分别阻止派单 | 课程模拟证书不是现实资质认证；不得把历史文本当已审核 |
| 业务资源 | 新建并更新机构照片/区域、项目价格/时长/状态、套餐组成及频次、培训、年限；重启查询；旧订单快照不随项目修改 | 套餐没有支付或周期自动下单 |
| 老人和权限 | 修改本人档案；尝试访问他人档案、附件、健康信息；管理员注销有未完事项者应先被阻止；历史不物理删除 | 不新增家属代理账号角色 |
| 健康 | 保存用药、就诊及个人阈值；禁用或调整阈值后新增测量核对预警；拒绝 NaN、无穷、无效日期；同日多次记录均可查 | 软件输入范围不是医疗诊断；7/30/90 天缺测不得补造 |
| 设备导入 | 使用测试设备编号/来源/外部标识提交一条模拟测量，再次提交同标识应去重；检查界面模拟说明 | 未接真实硬件，不认定自动同步成功 |
| 记录和反馈 | 实际起止、过程、观察、耗材、专项信息、真实附件；管理员退回修改后重提，通过才可评价；投诉申诉、回复和结案 | 只有附件文件和下载可查才算证据，“照片 1 张”不能代替文件 |
| 应急与通知 | 老人立即求助；拒绝定位后仍登记档案地址；管理员前台应收到站内通知；30 秒后或派单后不得取消；人员派单、出发、到达、处理和误报留痕 | 单独实测可见页面 10 秒目标；无外部配置显示未配置，模拟联系人确认明确标注 |
| 定位和地图 | 人员在执行中授权定位，核对坐标更新时间；超过五分钟显示距离未知；复制坐标/主动打开地图 | 无假坐标，不承诺后台定位和内置导航 |
| 统计与导出 | 固定日期、社区、类型与人员筛选，核对页面、statistics API、SQL、Excel/PDF 数量；超过一页数据要核对总量 | 取消单不进履约率分母；三项均分>=4算好评；投诉按已履约订单去重；缺失时间不当零 |
| 附件安全 | 上传真实 PDF/PNG/JPEG/WebP；伪造类型、超 12MB、越权下载和路径穿越应失败 | 文件归属授权不可用前端隐藏替代 |
| 恢复和容量 | 见下节；保留 SHA 清单、生成报告、负载报告与恢复前目录 | 数据量和并发必须来自实际运行，不以界面数字代替 |

慢病覆盖采用课程口径：有慢病标签且期内有健康登记/随访的老人比例；应急响应时间为登记到首次派单，到达时长单列。缺失时间不当零。验收时还应检查文字输入在页面显示时被转义，切换账号后不残留上一角色数据。

## 三、恢复演练

1. 在隔离库上传真实附件并记录对象、文件名、下载内容和数据库行。
2. 停止该服务器；`python -m tools.operations backup --source C:\care-acceptance-demo --destination C:\care-backups\exercise --server-stopped`。
3. 运行 verify；复制一份快照，修改其任一附件，verify 和 restore 均必须失败，目标不能被改变。
4. 恢复未修改快照到空数据目录，重启 `server.py --data-dir` 指向该目录，用原角色下载附件并核对内容/关系。
5. 非空目标默认应拒绝；显式 `--replace` 后确认同级 `*-before-restore-*` 仍含恢复前完整目录。留存副本不自动删除。

快照检查覆盖整库 SQLite 完整性、外键、附件登记文件存在性、全文件 SHA 和路径安全。停机是使用者的必要前提，脚本不能通过一个参数强制其他程序停止。不要将恢复目标指向源码工程目录。

## 四、数据量和负载

按 README 在独立目录生成 50000 老人、800 人员、300000 订单和可配置健康记录。固定 seed 下业务行可重建；生成文件已经存在时必须拒绝覆盖。先小规模验证工具，再酌情运行完整规模。用迁移后的隔离库作为 `--template` 可复制最新 schema。

负载工具分别支持 admin/elder/provider 登录，只读请求按登录角色被服务端限定范围。记录数据库实际数量、并发请求工作线程、总请求数、持续时间、吞吐、p50/p95/p99/最大时延、HTTP/网络错误和错误中出现的锁冲突。锁冲突数量仅指服务端响应中可观察的 `locked/busy`，不是服务器内部锁等待计数。终端密码不写进报告。

大规模数据生成完成不等于大规模并发通过；8 个工作线程不等于 2000 名在线用户。2000 同时在线、写入压力、长时间稳定性、真实设备、短信/微信、后台推送、GPS 与地图、旧 Android APK 均需另行实测，不写“已通过”。
