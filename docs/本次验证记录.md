# 课程验收版验证记录

验证日期：2026 年 10 月 26 日。环境：Windows 11、Python 3.12.14、桌面 Edge 无界面浏览器。业务测试使用原始数据库的临时副本；容量测试使用独立生成库。原始压缩包、D 盘工程及交付目录中的基准数据库不承担测试写入。

## 代码改进范围

| 核心部分 | 已落实内容 |
|---|---|
| 档案、资源与资格 | 老人档案、优先级、证件照及历史；机构、项目与套餐；人员资质提交、审核、到期提醒和培训；角色归属与管理字段限制；注销原因及历史保留 |
| 预约、履约与反馈 | 预约条件校验、完整时段与跨日预约、事务派单和并发冲突校验、项目名称与价格快照；出发到达完成；未执行和部分完成原因；专项记录、耗材及附件；记录审核、退回重提、评价和投诉结案 |
| 健康、应急与运维 | 用药、就诊、个人阈值和真实测量；课程设备数据去重导入；立即求助、服务端取消规则和站内通知；位置上报；真实统计与筛选导出；分页检索、备份恢复及容量工具 |

## 自动化与页面实测

- `python -m unittest discover -s tests -t . -v`：62 项通过，耗时 63.088 秒。覆盖越权、管理字段、重复迁移、密码升级、并发重叠、无效输入、跨日边界、异常记录、审核评价、附件、统计、备份恢复、隔离数据生成及三角色完整履约流程。原始输出见 `validation/unittest-final.log`。
- `node tests/frontend-check.cjs` 及三份 JavaScript 语法检查通过。行为检查覆盖转义、数值转换、记录与评价附件、长时预约、立即求助和退出后的定时器清理。
- Playwright 实际浏览器验证完成 44 次页面访问，覆盖管理员、老人、人员及游客。通过页面表单新增服务项目，刷新后查到持久数据；老人提交跨日 24 小时预约；人员保存可编辑资料；刷新恢复登录后正常退出。未出现页面 JavaScript 异常。记录见 `validation/browser-results.json`。
- 老人点击求助后，管理员前台通知页在本轮实测中约 7.788 秒显示该求助；随后取消请求成功。该结果是一次本机前台实测，不代表所有设备和网络均达到相同响应时间。
- 检查 1440×1000 桌面页面及 390×844 手机登录布局截图；未在实体手机或旧 APK 上完成验收。
- 在 30 万订单、800 人员库导出 Excel 和 PDF，Excel 人员明细为 800 行，PDF 为 75 页，核对包含首末人员。另有超过 100 人的筛选导出回归测试，防止静默截断。见 `validation/export-results.json`。

## 数据量与有限负载

独立生成 50000 名老人、800 名人员、300000 条订单及 300000 条健康记录，生成耗时约 19.049 秒。服务启动后接口核对的老人、人员与订单数量分别为 50000、800、300000。

本轮只读负载交替访问管理员订单第一页与统计接口，共 24 次请求、4 个并发工作线程：

| 指标 | 本次结果 |
|---|---:|
| 持续时间 | 8.835643 秒 |
| 吞吐 | 2.716 次/秒 |
| 中位时延 | 722.615 毫秒 |
| p95 时延 | 6153.504 毫秒 |
| 最大时延 | 6255.129 毫秒 |
| 请求错误 / 可观察锁错误 | 0 / 0 |

原始机器信息、请求路径及采样结果见 `validation/load-final.json`。统计已改为 SQL 批量聚合并加入写后失效缓存，但此规模下统计仍可能等待数秒；不能据此宣称达到 2000 人同时在线、生产响应时间或写入容量目标。

## 交付与边界

首次打开已有数据库时，系统执行增量迁移并保存数据库副本。旧证书以待审核状态导入，经审核后才参与派单。数据库与附件的完整备份步骤见 README。

真实短信、微信、联系人回执和硬件设备尚未连接；课程模拟入口有明确标识。站内通知依赖页面前台轮询，位置上报依赖浏览器授权。旧 Android APK 未重新构建，ZIP 不包含该旧包。实体移动端、后台推送、长时稳定性及 2000 人在线均需后续实测。管理员预约下拉选项仍适用于课程样本规模；5 万老人场景下的远程检索选择器尚未优化，不能把目录分页等同于全部大规模操作体验已完成。

仓库随附的演示数据库由项目内置样例生成。代码可在本地直接运行。
